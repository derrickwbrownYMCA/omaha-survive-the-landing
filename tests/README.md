# Soldier visual checks

`Soldier visual checks` runs four independent captures for each PR: actual base and head checkouts, on a 1280×720 desktop and an 844×390 landscape touch viewport. Manual dispatch tests the **fixed public GitHub Pages site**, on both viewports, against the selected ref. Dispatch on the revision you expect to be deployed. There is no deploy step; a stale deployed HTML, script, or GLB fails the identity check.

Each `soldier-{source}-{screen}` artifact contains full browser-rendered PNGs and `capture.json`. Compare matching filenames side by side. The trace gives revision, asset digests, player positions, game times, active clips, stance/lean samples, staging, and errors. The 11 images are chronological: rail brace, returned look, sprint, stop, crouch transition, held crouch, rise, standing, wave, response window, grip. Natural variation in soldiers, terrain, battle effects, and event timing means these are **not** pixel-equality goldens. Review the visible hands, eye lines, delayed response and readability; a green job isn't an aesthetic verdict.

Chromium runs muted with SwiftShader, DPR 1, and the game's low quality setting. No renderer, animation, screenshot or input handlers are replaced. Start, skip, movement and stance use player controls, including genuine Chromium touch events for the joystick/toggles. On head and Pages the phone switches view in the Controls panel. Earlier touch builds use the preexisting third-person URL. To isolate sprint from the game's deep-water movement penalties, the harness moves the player to dry sand after the actual landing. Desktop advances the uncaptured boat passage using native simulation steps after Space skips the intro; all control and pose captures run at the browser’s normal frame cadence. The trace checks that the same gear meshes stay attached to the original two actors after landing. For the three closeups only, the HUD is hidden and the camera follows real actors on dry sand. If an unobstructed pair is unavailable, their positions are staged and recorded. The game gesture API cues only the sender; frames are sampled to check that one listener actually starts posing after a delay. This does not measure how often the encounter occurs. The final frame is an oblique close-up of an AI soldier’s carry. Browser emulation does not certify performance, audio quality, or physical phone hardware.
